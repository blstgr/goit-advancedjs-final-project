## 1. Огляд

Командний проєкт курсу "Advanced JavaScript and TypeScript: Tools and Best Practices". Команда потоку разом верстає та збирає сайт за наданим дизайн-макетом і технічним завданням, використовуючи Vite як бандлер, з повним циклом Git-флоу (гілки, злиття, вирішення конфліктів), плануванням через Trello та фінальним деплоєм на GitHub Pages.

**Мета навчання** (не є критеріями приймання коду, але задають контекст роботи):
- досвід командної розробки та Git-колаборації (branching/merging, conflict resolution);
- досвід роботи з бандлером Vite;
- досвід планування задач через Trello;
- опційно: ролі Team Lead / Scrum Master;
- досвід презентації проєкту.

### 2.1 Структура проєкту (приклад із відео "Як здати командний проєкт у LMS")

Відео саме про структуру проєкту не розповідає — це приклад structure, показаний на екрані як зразок готового репозиторію, який здається. Орієнтир для Team Lead, не обов'язкова до копіювання схема:

```
.github/
assets/
src/
  css/
    header.css
    reset.css
    styles.css
  img/
  partials/
    about.html
    footer.html
    header.html
    hero.html
  public/
  index.html
  main.js
.editorconfig
.gitignore
.prettierrc.json
package.json
package-lock.json
README.md
vite.config.js
```

Примітки:
- `src/css`, `src/img`, `src/partials` — розбивка стилів/зображень/HTML-партиалів по підпапках усередині `src` (зображення тут відповідають вимозі `src/images` з [6.2](#62-зображення) — назва підпапки може відрізнятись, суть та ж)
- `partials/*.html` — окремі HTML-фрагменти на секцію (header, hero, about, footer тощо), що потім збираються в `index.html` (типовий підхід при верстці на Vite з `vite-plugin-html`/`posthtml-include` або аналогом)
- `.editorconfig`, `.prettierrc.json` — узгоджений стиль коду для всієї команди
- У прикладі з відео присутні кілька `README.*.md` (мовні варіанти опису репозиторію) — для цього проєкту достатньо одного `README.md`
- Це саме **приклад**, а не обов'язкова вимога курсу — фінальну структуру папок/файлів затверджує Team Lead (див. [6.4](#64-нейминг-та-стиль-коду) та відкрите питання в [10](#10-відкриті-питання-уточнити-з-team-lead--ментором))

### 2.2 Компонентна архітектура

Проєкт будується як **бібліотека переюзабельних компонентів**, а сторінки — лише композиція з них, а не написані з нуля щоразу.

- **Дизайн-токени.** Усі кольори, розміри шрифтів, радіуси, іконки, відступи — CSS-змінні в `src/css/variables.css` (`--color-*`, `--fs-*`/`--lh-*`, `--radius-*`, `--space-*`, `--size-icon-*`). У жодному CSS-файлі компонента не повинно бути "магічних чисел" (хардкоджених px/кольорів) — лише посилання на токени. Якщо потрібне нове значення — спочатку додати токен, а не вписувати число напряму.
- **Один компонент — один набір файлів.** Кожен UI-елемент (кнопка, пошук, перемикач меню, рейтинг, пагінація, соц. іконки, картка категорії/вправи тощо) живе як власний `.css`-файл у `src/css/components/`, за потреби — власний HTML-партиал у `src/partials/` і власний JS-модуль у `src/js/`. Не дублювати розмітку компонента в кількох місцях — переиспользувати той самий партиал/клас.
- **Сторінки збираються, а не пишуться.** `index.html`, `favorites.html` тощо підключають готові партиали (`<load src="..." />` через `vite-plugin-html-inject`) — Header, Footer та кожен блок сторінки. Логіка сторінки — це підключення потрібних компонентів у потрібному порядку, без копіювання їхньої внутрішньої розмітки.
- **Іменування компонентів** — БЕМ-подібне: `.block__element`, модифікатори через `.block--modifier` та стан через `.is-state`/`.is-active` (вже застосовано в наявних компонентах — `.btn--favorite`, `.nav-toggle__link.is-active` тощо).

## 4. API

Базовий URL: `https://your-energy.b.goit.study/api`
Документація (Swagger): https://your-energy.b.goit.study/api-docs

| Опис | Метод | Ендпоінт | Параметри |
|---|---|---|---|
| Перелік фільтрів (категорій) вправ | `GET` | `/filters` | `filter` (назва фільтру), `page`, `limit` — усі опційні |
| Перелік вправ з фільтрацією | `GET` | `/exercises` | `bodypart`, `muscles`, `equipment`, `keyword`, `page`, `limit` — усі опційні |
| Детальна інформація про вправу | `GET` | `/exercises/{exerciseId}` | — |
| Додати рейтинг вправі | `PATCH` | `/exercises/{exerciseId}/rating` | тіло запиту — оцінка |
| Цитата дня | `GET` | `/quote` | — |
| Підписка на розсилку нових вправ | `POST` | `/subscription` | тіло запиту — email |

Приклади запитів:
```
GET https://your-energy.b.goit.study/api/filters?filter=Muscles&page=1&limit=12
GET https://your-energy.b.goit.study/api/exercises?bodypart=back&muscles=lats&equipment=barbell&keyword=pull&page=1&limit=10
```

> Усі параметри запитів опційні — кожен можна прибрати за потреби (наприклад, `GET /exercises?bodypart=back` без інших фільтрів).

## 5. Базова версія (MVP)

### 5.1 Header

- **Mobile:** логотип + бургер-меню (навігація + перелік соц. мереж)
- **Tablet & Desktop:** логотип, навігація, перелік соц. мереж
- Click по логотипу або пункту "Home" → перехід на головну сторінку
- Click по "Favorites" → сторінка з переліком вправ, доданих користувачем до улюблених
- Click по бургер-меню → меню розгортається на всю висоту viewport
- Перелік соц. мереж — `<ul>` зі списком елементів, кожне посилання відкривається у новій вкладці:
  - Facebook — https://www.facebook.com/goITclub/
  - Instagram — https://www.instagram.com/goitclub/
  - YouTube — https://www.youtube.com/c/GoIT
- Іконки соц. мереж — формат SVG

### 5.2 Home

Складається з блоків:
1. Герой (заголовок сайту + популярні теги)
2. Панель фільтрів
3. Перелік категорій / вправ (залежно від обраного фільтру)
4. Цитата дня + інформаційний блок про 110 хвилин спорту щоденно

**Герой**
- Статичний контент: заголовок сайту, підзаголовок, перелік популярних тегів, зображення (контентні, не фонові)

**Панель фільтрів**
- Заголовок секції
- Фільтри у вигляді кнопок; click по кнопці → запит категорій за відповідним фільтром + стилізація кнопки як активної

**Цитата дня**
- Цитата отримується з backend і зберігається в `localStorage` разом з датою отримання
- При повторному завантаженні: якщо дата в `localStorage` збігається з поточною — запит на backend не робити, використати збережене значення
- Статичний інформаційний блок про важливість 110 хв спорту щоденно

**Блок категорій**
- Категорії відмальовуються з урахуванням обраного фільтру
- За замовчуванням (перший вхід на Home) — фільтр `Muscles`, кнопка "Muscles" стилізована як активна
- Якщо категорій не знайдено — показати повідомлення користувачу
- **Картка категорії:** зображення, назва категорії, фільтр, до якого вона належить
- Click по картці категорії → перелік категорій приховується, відмальовується перелік вправ обраної категорії

**Блок вправ**
- Вправи відмальовуються з урахуванням обраного фільтру та категорії
- Поряд із заголовком секції — назва обраної категорії
- Поряд із кнопками-фільтрами — пошукова строка (пошук за ключовим словом у назві вправи, подія `submit`)
- Пошук враховує: фільтр, категорію, ключове слово (за наявності), кількість вправ на сторінці, порядковий номер сторінки
- Якщо вправ не знайдено — показати повідомлення користувачу
- **Картка вправи:** назва, кількість калорій за 3 хв виконання, задіяна частина тіла, мета виконання, рейтинг, кнопка "Start" (відкриває модальне вікно з детальною інформацією)
- Пагінація — "серверна": порядковий номер сторінки та кількість елементів передаються як параметри запиту до backend

### 5.3 Modal window — Exercise

Містить:
- Відео з прикладом виконання вправи (за наявності)
- Назву вправи
- Рейтинг вправи
- Мету виконання
- Задіяну частину тіла
- Популярність вправи серед користувачів
- Кількість калорій за 3 хв виконання
- Короткий опис
- Кнопку додавання/видалення вправи з Favorites
- *(Додатково, опційно)* кнопку проставлення оцінки вправи з прив'язкою до email — додавати "Give a rating" у модальне вікно лише якщо ця функціональність реалізована

Поведінка:
- Click по кнопці Favorites → оновлення переліку улюблених, збереженого в `localStorage`
- Закриття модального вікна: click по backdrop, click по кнопці-хрестику, клавіша `ESC` — в усіх трьох випадках слухачі подій знімати після закриття

### 5.4 Favorites

- Блок з цитатою дня + інформаційний блок про 110 хв спорту (як на Home)
- Блок з переліком вправ, доданих до Favorites (джерело даних — `localStorage`)
- Якщо улюблених вправ не знайдено — показати повідомлення користувачу
- **Картка вправи:** назва, кількість калорій за 3 хв виконання, задіяна частина тіла, мета виконання, кнопка "Start" (відкриває модальне вікно) та кнопка-іконка видалення вправи з улюблених

### 5.5 Footer

- Логотип (click → перехід на головну сторінку)
- Перелік посилань на соц. мережі — ідентично Header (`<ul>`, SVG-іконки, нова вкладка): Facebook, Instagram, YouTube (посилання вище)
- Слоган компанії
- Форма підписки на розсилку нових вправ:
  - Обов'язкове поле `email`
  - Валідація атрибутом `pattern`: `^\w+(\.\w+)?@[a-zA-Z_]+?\.[a-zA-Z]{2,3}$`
  - Кнопка `type="submit"` — "Send"
  - При валідному значенні — запит на створення підписки до backend (`POST /subscription`)

## 9. Процес роботи (рекомендований)

1. **Планування:** декомпозиція макета на завдання, картки в Trello, розподіл ролей (Team Lead / Scrum Master — опційно)

3. **Розробка:** верстка секцій відповідно до макета, з мобільного брейкпоінта до десктопного (mobile-first) або навпаки — за рішенням команди
4. **Оптимізація:** стиснення зображень, перевірка валідаторами, аудит PageSpeed
5. **Деплой:** публікація на GitHub Pages через гілку `gh-pages` або GitHub Actions
6. **Прибирання:** видалення відпрацьованих гілок
7. **Код-ревʼю:** фінальний перегляд ментором
8. **Презентація проєкту**
